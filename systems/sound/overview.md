# sound: overview

The client's sound: the engine over FMOD that opens, places, fades and mixes every sound; the
SoundEntries definitions and the plays built on them; the interface's start-up, CVars and Lua
functions; the music; the ambience, reverb, water and emitter loops; and the sound side of the
unit, item and combat sounds.

The system owns ten object files, listed below; `0x827000`, the C runtime's initializer table,
lists each one's static initializers in one run. The docs split by topic: `engine` (the `Sound`
object over FMOD), `entries` (definitions, file picks and plays), `interface` (start-up, CVars,
Lua, interface and named sounds), `music`, `ambience` and `objects`. This doc holds the object
files, their static initializers, the containers they share and the code nothing reaches. Other
systems enter through the roots each topic doc lists, and through the static initializers below.

## Hash tables

The footstep table, the UI sound name table, the sheathe table and the definition load's string
table share one hash table template: a vtable, a node list, a walk counter, an array of bucket
lists and a mask, −1 while empty. An add makes four buckets on first use; while the mask is below
0x1fff it lowers the counter by 3 (not below 0) and raises it once per link in the bucket, and

## Lists and growable arrays

A list link is two words, the previous link and the next, with bit 0 of the next marking the end;
an explicit list holds its link offset (0xdddddddd until set) and a head linked to itself. A

largest power of two not above the request, capped at 21 for bucket lists, 64 for pointer arrays,
